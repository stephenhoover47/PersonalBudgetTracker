# Personal Budget Tracker Frontend

This is a React-based frontend for the Personal Budget Tracker application. The frontend provides user authentication and Plaid account linking functionality.

## Setup Instructions

### Prerequisites

- Node.js (v14 or later)
- npm or yarn
- Backend API running (either locally or deployed)

### Installation

1. Clone the repository (if you haven't already)
2. Navigate to the frontend directory:
   ```
   cd /path/to/PersonalBudgetTracker/frontend
   ```
3. Install dependencies:
   ```
   npm install
   ```

### Configuration

Before running the application, you need to configure the API endpoint:

1. Edit the `src/api/config.ts` file
2. Replace the `API_BASE_URL` value with your backend URL:
   ```typescript
   export const API_BASE_URL = process.env.NODE_ENV === 'production'
     ? 'https://your-railway-app-url.up.railway.app' // Your backend URL
     : '/api';
   ```

### Development

To run the application in development mode:

```
npm run dev
```

This will start the development server at http://localhost:3000

The webpack dev server is configured to proxy API requests to your backend to avoid CORS issues. The proxy is set up to forward all requests from `/api` to your backend server (configured to run at `http://localhost:8000` by default).

### Testing Production Build Locally

To test the production build locally:

```
npm run start:prod
```

This will build the application and start the Express server that serves the static files.

## Deployment to Railway

### What's Needed for Railway Deployment

The frontend includes several files specifically for Railway deployment:

1. **server.js** - An Express server that serves the built React app
2. **railway.toml** - Railway configuration file
3. **Dockerfile** - Multi-stage build for containerized deployment (alternative)

### Deploying to Railway

#### Option 1: Using Railway CLI

1. Install the Railway CLI:
   ```
   npm install -g @railway/cli
   ```

2. Login to your Railway account:
   ```
   railway login
   ```

3. Link to your existing Railway project (or create a new one):
   ```
   railway link
   ```

4. Deploy the frontend:
   ```
   railway up
   ```

#### Option 2: Using GitHub Integration

1. Push your code to a GitHub repository
2. In the Railway dashboard, create a new service
3. Choose "Deploy from GitHub repo"
4. Select your repository and branch
5. Railway will automatically detect the build configuration

### Environment Configuration

In the Railway dashboard:

1. Go to your frontend service
2. Click on "Variables"
3. Add any necessary environment variables:
   - `NODE_ENV` = "production"
   - `PORT` = 3000 (or let Railway assign it)
   - `API_URL` = Your backend URL (if needed)

### Configuring for Development and Production

For a multi-environment setup:

1. Create separate services in Railway for development and production
2. Configure environment variables accordingly:
   - For development: `NODE_ENV=development`
   - For production: `NODE_ENV=production`

3. Deploy different branches to different services:
   - Deploy `main` branch to production
   - Deploy `dev` branch to development

### Connecting Frontend and Backend

To make your frontend communicate with your backend:

1. Get the URL of your deployed backend service from Railway
2. Update the `src/api/config.ts` file:
   ```typescript
   export const API_BASE_URL = process.env.NODE_ENV === 'production'
     ? 'https://your-backend-railway-url.up.railway.app'
     : '/api';
   ```
3. If using Railway environment variables, you can use:
   ```typescript
   export const API_BASE_URL = process.env.API_URL || '/api';
   ```

## Understanding the Express Server (server.js)

The Express server serves several important purposes:

1. **Serving Static Files**: It serves the compiled React app (from the `dist` folder generated by webpack)

2. **Client-Side Routing Support**: Since React Router handles routing on the client side, the server returns `index.html` for all routes to allow the client-side router to take over

3. **Required for Railway**: Railway expects a server that listens on a port; this server fulfills that requirement

4. **Health Checks**: Provides a `/health` endpoint that Railway uses to verify your service is running

## Additional Notes

- The frontend uses React Router for navigation
- Authentication is handled via JWT tokens stored in localStorage
- All API requests to the backend include the auth token in the Authorization header
- The Plaid Link integration uses the `react-plaid-link` package
